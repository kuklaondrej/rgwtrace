# rgwtrace

`rgwtrace` traces Ceph RGW request activity and exports request-oriented telemetry.

The project is intentionally split into:

- C eBPF probes for low-level Ceph/RGW uprobes.
- Rust userspace for typed event decoding, request aggregation, classification, and telemetry export.

Initial versions consume DWARF JSON generated by `cephtrace` so this repository can build on the proven probe locations and offsets without reimplementing DWARF parsing first.

## Planned MVP

- Correlate RADOS operations with RGW `trans_id`.
- Represent each RGW request as a trace span.
- Attach RADOS operations as span events when they complete within the request window.
- Emit background RGW work as standalone spans.
- Support JSON debug output first, then OTLP output for Tempo and VictoriaTraces.

## Current Status

Implemented:

- Fixed BPF/Rust event ABI for RGW request start/end and RADOS operations.
- C eBPF source derived from the working `cephtrace` `radostrace` probes.
- Rust parser for existing `cephtrace` DWARF JSON files.
- Linux BPF skeleton generation through `libbpf-cargo`.
- Linux live tracing loop with uprobe attachment, hprobe map population, and ring buffer decoding.
- RGW/RADOS classification rules for S3 data, metadata, auth, GC, notify, sync, and config operations.
- Request aggregation that attaches RADOS operations as events on an `rgw.request` span when `trans_id` is available.
- JSON trace output and minimal OTLP/HTTP JSON export.
- Trace flushing on `Ctrl-C` or `--timeout`.

Not implemented yet:

- Grace-period flushing for late async RADOS operations.
- Native DWARF parsing; `rgwtrace` still consumes JSON generated by `cephtrace`.

## Usage

Validate DWARF JSON parsing and emit an empty trace document without tracing:

```sh
rgwtrace --import-json 18.2.8-1jammy_dwarf_traceid.json --dry-run --output json
```

Run live tracing and flush JSON on `Ctrl-C`:

```sh
sudo rgwtrace --import-json 18.2.8-1jammy_dwarf_traceid.json --output json
```

Run live tracing for a fixed interval:

```sh
sudo rgwtrace \
  --import-json 18.2.8-1jammy_dwarf_traceid.json \
  --timeout 30 \
  --output json
```

Send the current trace document to an OTLP/HTTP endpoint:

```sh
rgwtrace \
  --import-json 18.2.8-1jammy_dwarf_traceid.json \
  --output otlp \
  --otlp-endpoint http://localhost:4318/v1/traces
```

The OTLP exporter currently supports plain `http://` endpoints, which matches the common local OpenTelemetry Collector path for Tempo and VictoriaTraces.

When automatic target discovery is not enough, pass explicit paths:

```sh
sudo rgwtrace \
  --import-json 18.2.8-1jammy_dwarf_traceid.json \
  --librados-path /lib/librados.so.2 \
  --librbd-path /lib/librbd.so.1 \
  --libceph-common-path /usr/lib/ceph/libceph-common.so.2 \
  --radosgw-path /usr/bin/radosgw
```

## Build Notes

Live tracing builds and runs on Linux only. Building the BPF skeleton requires a working eBPF toolchain, including clang, libelf development headers, and kernel/libbpf-compatible headers.

The macOS build is intentionally kept working for parser/classifier/exporter development, but it cannot validate the Linux-gated BPF loader.

## Trace Model

Default request output:

```text
Span: rgw.request
  Event: rados.op
  Event: rados.op
```

Fallback output for operations without `trans_id`:

```text
Span: rgw.background.rados_op
  Event: rados.op
```
